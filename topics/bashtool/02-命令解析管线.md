# 02 命令解析管线

> 想可靠地拦截 `IFS=$'\n'` 这种攻击，regex 不够——必须把 bash 字符串解析成 AST。本篇拆 Claude Code 的命令解析层：12K 行代码、tree-sitter + shell-quote 双路径、fail-closed 设计。

## 2.1 为什么 regex 不够

考虑这个命令：

```bash
ti"meout" 30 rm -rf /
```

肉眼看是 `timeout 30 rm -rf /`——`ti"meout"` 在 bash 里和 `timeout` 等价（双引号包裹的部分被 unquote）。

regex 怎么识别？`/^timeout /`? 不行——它前面有 `ti"`。`/^ti.*meout/`? 也不行——这个 regex 会过度匹配。

真正的解法是**把字符串解析成 AST**：

```
command
  ├─ name: "timeout"    (合并 ti + "meout" 的 unquoting 结果)
  ├─ arg: "30"
  └─ arg: "rm -rf /"
```

AST 上的 "name" 字段就是 `timeout`——bash 自己 unquote 完的结果，不是字符串字面值。

这就是为什么 `utils/bash/` 目录有 12K 行代码——bash 是出了名难解析的语言。

## 2.3 SimpleCommand —— 解析的目标结构

`ast.ts:31-40`：

```ts
export type SimpleCommand = {
  /** argv[0] is the command name, rest are arguments with quotes already resolved */
  argv: string[]
  /** Leading VAR=val assignments */
  envVars: { name: string; value: string }[]
  /** Output/input redirects */
  redirects: Redirect[]
  /** Original source span for this command (for UI display) */
  text: string
}
```

每个**简单命令**（`ls -la /tmp` 这种、不含 `&&` / `|` / 子 shell 的）解析后是这种形态。`argv` 是 unquote 之后的，`envVars` 是前导变量赋值，`redirects` 是 `>`、`<` 等重定向，`text` 是原始字符串（UI 显示用）。

`ParseForSecurityResult`（`ast.ts:42-45`）是 3 选 1：

```ts
export type ParseForSecurityResult =
  | { kind: 'simple'; commands: SimpleCommand[] }
  | { kind: 'too-complex'; reason: string; nodeType?: string }
  | { kind: 'parse-unavailable' }
```

3 种结果的下游处理：

- `simple` → 可以基于 argv 做精确权限决策；
- `too-complex` → 把命令当不可知"黑盒"，降级问用户；
- `parse-unavailable` → tree-sitter 模块没加载（外部环境），降级走 legacy 路径。

## 2.4 Fail-closed —— 整套解析的核心设计

`ast.ts:1-19` 的文件头注释把整个设计点说得很清楚：

> AST-based bash command analysis using tree-sitter.
>
> This module replaces the shell-quote + hand-rolled char-walker approach in bashSecurity.ts / commands.ts. Instead of detecting parser differentials one-by-one, we parse with tree-sitter-bash and walk the tree with an EXPLICIT allowlist of node types. Any node type not in the allowlist causes the entire command to be classified as 'too-complex', which means it goes through the normal permission prompt flow.
>
> The key design property is **FAIL-CLOSED**: we never interpret structure we don't understand. If tree-sitter produces a node we haven't explicitly allowlisted, we refuse to extract argv and the caller must ask the user.
>
> This is NOT a sandbox. It does not prevent dangerous commands from running. It answers exactly one question: "Can we produce a trustworthy argv[] for each simple command in this string?" If yes, downstream code can match argv[0] against permission rules and flag allowlists. If no, ask the user.

**Fail-closed allowlist** 是整个架构的根。新版本的 bash 加了新语法、tree-sitter 多解析出一种节点——Claude Code 默认**不理解** = **拒绝放行**。这避免了"新语法漏过老解析器"的攻击窗口。

## 2.5 Pre-checks —— tree-sitter 之前的 regex 拒绝

`ast.ts:408-437` 在 tree-sitter 解析之前先跑 5 类 regex，专门捕获 **tree-sitter 和 bash 在词边界判断上的分歧**：

```ts
if (CONTROL_CHAR_RE.test(cmd)) {
  return { kind: 'too-complex', reason: 'Contains control characters' }
}
if (UNICODE_WHITESPACE_RE.test(cmd)) {
  return { kind: 'too-complex', reason: 'Contains Unicode whitespace' }
}
if (BACKSLASH_WHITESPACE_RE.test(cmd)) {
  return { kind: 'too-complex', reason: 'Contains backslash-escaped whitespace' }
}
if (ZSH_TILDE_BRACKET_RE.test(cmd)) {
  return { kind: 'too-complex', reason: 'Contains zsh ~[ dynamic directory syntax' }
}
if (ZSH_EQUALS_EXPANSION_RE.test(cmd)) {
  return { kind: 'too-complex', reason: 'Contains zsh =cmd equals expansion' }
}
if (BRACE_WITH_QUOTE_RE.test(maskBracesInQuotedContexts(cmd))) {
  return { kind: 'too-complex', reason: 'Contains brace with quote character (expansion obfuscation)' }
}
```

注释（`ast.ts:404-407`）：

> Pre-checks: characters that cause tree-sitter and bash to disagree on word boundaries. These run before tree-sitter because they're the known tree-sitter/bash differentials.

每一条都是真实的 attack vector：

- **控制字符**：`rm$'\033[2K'-rf` 这种用控制字符隐藏的命令；
- **Unicode 空白**：U+00A0（不间断空格）等被 bash 当词分隔符但 tree-sitter 当词内；
- **backslash 空白**：`rm\<TAB>-rf /` ——backslash + tab 在 bash 是空格，但 tree-sitter 可能误判；
- **zsh 语法**：`~[dir]` / `=cmd` 是 zsh 特有的扩展，tree-sitter-bash 不识别；
- **引号里的 brace**：`echo "rm{}"` 这类用 brace expansion 在引号里混淆词边界。

这 6 类是**已知的解析器分歧**——直接拒绝比试图模仿 bash 的解析行为更安全。

## 2.6 解析后的 AST 漫游

`ast.ts:462+` 的 `walkProgram` 从 tree-sitter 的根节点开始递归。两个关键集合：

`ast.ts:54-59`：

```ts
const STRUCTURAL_TYPES = new Set([
  'program',
  'list',
  'pipeline',
  'redirected_statement',
])
```

`ast.ts:61-65`：

```ts
const SEPARATOR_TYPES = new Set(['&&', '||', '|', ';', '&', '|&', '\n'])
```

**STRUCTURAL_TYPES** 是"组合命令的容器"——`a && b` 在 tree-sitter 里是 `list` 节点包着 `command(a)` / `&&` 分隔符 / `command(b)`；`a | b` 是 `pipeline` 节点。**遇到这种节点就递归子节点。**

**SEPARATOR_TYPES** 是"组合命令的分隔符"——跳过它们。

任何**不在 STRUCTURAL_TYPES 也不是 command/declaration_command/comment** 的节点 → 触发 fail-closed → 返回 `too-complex`。这条规则就是 "**EXPLICIT allowlist**" 的实现。

## 2.7 关键巧思：var scope 跨分隔符切换

`ast.ts:504-565` 的 `STRUCTURAL_TYPES` 处理分支有非常细的安全考虑：

```ts
// SECURITY: `||`, `|`, `|&`, `&` must NOT carry varScope linearly. In bash:
//   `||` RHS runs conditionally → vars set there MAY not be set
//   `|`/`|&` stages run in subshells → vars set there are NEVER visible after
//   `&` LHS runs in a background subshell → same as above
// Flag-omission attack: `true || FLAG=--dry-run && cmd $FLAG` — bash skips
// the `||` RHS (FLAG unset → $FLAG empty), runs `cmd` WITHOUT --dry-run.
// With linear scope, our argv has ['cmd','--dry-run'] → looks SAFE → bypass.
```

注释里描述了一个真实的攻击：

```bash
true || FLAG=--dry-run && cmd $FLAG
```

`true` 永远成功 → `||` 的 RHS（`FLAG=--dry-run`）**永远不执行** → `&&` 因为 `true` 成功而执行 → `$FLAG` 是空 → `cmd` 没有 `--dry-run` 参数被运行。

如果解析器**线性传递 varScope**（把 `FLAG=--dry-run` 当作已赋值），argv 会被错误地认为是 `['cmd','--dry-run']`——看起来很安全（有 dry-run 不会真改东西）→ 误放行 → 实际上没 dry-run 真改了东西。

修复：**在 `||` / `|` / `&` 之后重置 varScope 到 snapshot**。`&&` / `;` 是顺序执行，保留 scope。

这是 AST 解析里**最容易做错的地方**之一——它要求解析器理解 bash 的语义，而不仅是语法。

## 2.8 placeholder 替换 —— 处理 $() 和 $VAR

`ast.ts:67-83`：

```ts
/**
 * Placeholder string used in outer argv when a $() is recursively extracted.
 * The actual $() output is runtime-determined; the inner command(s) are
 * checked against permission rules separately. Using a placeholder keeps
 * the outer argv clean (no multi-line heredoc bodies polluting path
 * extraction or triggering newline checks).
 */
const CMDSUB_PLACEHOLDER = '__CMDSUB_OUTPUT__'

/**
 * Placeholder for simple_expansion ($VAR) references to variables set earlier
 * in the same command via variable_assignment. Since we tracked the assignment,
 * we know the var exists and its value is either a static string or
 * __CMDSUB_OUTPUT__ (if set via $()). Either way, safe to substitute.
 */
const VAR_PLACEHOLDER = '__TRACKED_VAR__'
```

两种 placeholder：

### CMDSUB_PLACEHOLDER = '__CMDSUB_OUTPUT__'

对 `$(cmd)` 命令替换：把 **内部命令独立解析**（push 到 commands[] 单独检查），外层 argv 里放 placeholder。

例：`grep $(cat secret.txt) /etc/passwd` →
- 外层命令：argv = `['grep', '__CMDSUB_OUTPUT__', '/etc/passwd']`（permission 按 `grep:*` 决策）
- 内层命令：argv = `['cat', 'secret.txt']`（permission 按 `cat:*` 决策）

**两段独立做权限决策**——这避免了"内层泄露的内容"被当作外层命令参数处理。

### VAR_PLACEHOLDER = '__TRACKED_VAR__'

对在同一命令里赋值的 `$VAR` 引用：替换成 placeholder。例：

```bash
NOW=$(date) && jq --arg now "$NOW" ...
```

- `NOW=` 赋值被记录到 varScope；
- `$NOW` 引用 → 替换成 `__TRACKED_VAR__`；
- `argv` 看起来像 `['jq', '--arg', 'now', '__TRACKED_VAR__', ...]`；
- 这是安全的，因为 `$NOW` 的值是 `$(date)` 的输出，已经独立分析过。

### `containsAnyPlaceholder` 双向防御

`ast.ts:94-96`：

```ts
function containsAnyPlaceholder(value: string): boolean {
  return value.includes(CMDSUB_PLACEHOLDER) || value.includes(VAR_PLACEHOLDER)
}
```

如果用户的命令字符串里**恰好包含**了这俩 placeholder 字面值（攻击者刻意构造）—— `containsAnyPlaceholder` 会发现，这一段会被当 "**非 literal**" 不能信任。这是 defense-in-depth。

注释（`ast.ts:84-92`）：

> All placeholder strings. Used for defense-in-depth: if a varScope value contains ANY placeholder (exact or embedded), the value is NOT a pure literal and cannot be trusted as a bare argument. Covers composites like `VAR="prefix$(cmd)"` → `"prefix__CMDSUB_OUTPUT__"` — the substring check catches these where exact-match Set.has() would miss.

## 2.9 BARE_VAR_UNSAFE_RE —— 不带引号的 $VAR 拒绝

`ast.ts:98-110`：

```ts
/**
 * Unquoted $VAR in bash undergoes word-splitting (on $IFS: space/tab/NL)
 * and pathname expansion (glob matching on * ? [). Our argv stores a
 * single string — but at runtime bash may produce MULTIPLE args, or paths
 * matched by a glob. A value containing these metacharacters cannot be
 * trusted as a bare arg: `VAR="-rf /" && rm $VAR` → bash runs `rm -rf /`
 * (two args) but our argv would have `['rm', '-rf /']` (one arg).
 */
const BARE_VAR_UNSAFE_RE = /[ \t\n*?[]/
```

非常细的安全考虑：

```bash
VAR="-rf /" && rm $VAR
```

- 不带引号的 `$VAR` → bash 做 word splitting → 实际执行 `rm -rf /`（两参数）；
- 解析器看到 argv → `['rm', '-rf /']`（一参数）。

argv 和实际执行结果**不一致**——解析器以为只是删一个叫 "-rf /" 的文件，实际是删整个文件系统。

这条 regex 检测**变量值里有没有空白 / 通配符**，如果有 → bare $VAR 不能用 → fail-closed。

加引号 `"$VAR"` 的情况就安全了——bash 不做 word splitting / glob expansion，argv 一致。

## 2.10 commands.ts —— legacy shell-quote 路径

并行的 `splitCommandWithOperators`（`commands.ts:85+`）走的是另一条路径：基于 shell-quote 库。它**不要求** tree-sitter，所以外部环境也能用，但精度低。

输入：bash 字符串。输出：`string[]`——包含 operators 的 token 数组。例：

```js
splitCommandWithOperators("ls /tmp && rm -rf foo")
// → ['ls /tmp', '&&', 'rm -rf foo']
```

实现里有些非常细的"安全工程"：

### Heredoc 提前提取

`commands.ts:94`：

```ts
const { processedCommand, heredocs } = extractHeredocs(command)
```

shell-quote 库不正确解析 `<<EOF` heredoc，所以**提前提取**——把 heredoc 主体替换成 placeholder，解析完再 restore。

`utils/bash/heredoc.ts` (733 行) 专门处理这一块。

### Backslash-newline 续行处理

`commands.ts:96-119`：

```ts
// SECURITY: We must only join when there's an ODD number of backslashes before the newline.
// With an even number (e.g., `\\<newline>`), the backslashes pair up as escape sequences,
// and the newline is a command separator, not a continuation.
const commandWithContinuationsJoined = processedCommand.replace(
  /\\+\n/g,
  match => {
    const backslashCount = match.length - 1
    if (backslashCount % 2 === 1) {
      // Odd: last backslash escapes newline (line continuation)
      return '\\'.repeat(backslashCount - 1)
    }
    // Even: all backslashes pair up; newline is a separator, not continuation
    return match
  }
)
```

注释（97-105）描述了一个攻击：

```
tr\
aceroute
```

`tr` + backslash + newline + `aceroute` = bash 当作一个命令 `traceroute`。如果解析器以为这是两段（`tr` 和 `aceroute`），就漏检了 `traceroute`。

修复：奇数个 backslash → 续行 → 移除 backslash + newline 拼起来。偶数个 backslash → 转义对 → newline 仍是分隔符。

`commands.ts:122-139` 还有第二份续行处理——针对 fallback 路径的"原始命令"（不含 heredoc placeholder），防止：

```
echo "$\
{}" ; curl evil.com
```

- pre-join：`$` 和 `{}` 跨行 → `${}` 这个危险模式被切开；
- post-join：合并后 `echo "${}" ; curl evil.com` → curl 真执行。

如果 fallback 用 pre-join 字符串做权限检查，会以为是 `echo:*` 单一命令，放行 → 实际是 `echo` + `curl`。

`commands.ts:122-128` 注释明确这个 exploit。这种"在每个解析路径都加同样的安全处理" 体现纵深防御。

## 2.11 解析失败时的 fallback

`commands.ts:152-160`：


## 2.12 wrapper specs —— 透视器命令

`utils/bash/specs/` 下 7 个文件定义"透视"wrapper 命令：

```
specs/
├── alias.ts      —— alias 解析
├── nohup.ts      —— `nohup cmd args...` → 真命令是 cmd
├── pyright.ts    —— `pyright` 不算 wrapper 但有专门 spec
├── sleep.ts      —— sleep
├── srun.ts       —— `srun cmd args...`
├── time.ts       —— `time cmd` / `time -p cmd`
└── timeout.ts    —— `timeout 30 cmd args...` / `timeout --signal=KILL 30 cmd`
```

每个 spec 文件定义如何"剥掉外壳"。例如 `timeout`:

```bash
timeout 30 bazel build //...
```

应该被识别为 "真命令是 `bazel build //...`，timeout 只是 wrapper"。`timeout.ts` 的 spec 知道：

- argv[0] = `timeout`
- 跳过它后面的 duration（30）和可选 flag (`--signal=KILL`)
- 剩下的就是真命令

下游 permission 决策用这个 spec 把 `timeout 30 bazel build` 重写成 `bazel build`，然后按 `Bash(bazel build:*)` 规则匹配。

这是 `stripSafeWrappers`（`bashPermissions.ts:??`）的工作——会在 04 篇详细展开。

## 2.13 几个隐性设计判断

### 1. 双路径并存而不是单一替换

`splitCommand_DEPRECATED` 标了 deprecated 但没删——因为：
- tree-sitter 路径需要 WASM 模块加载（异步、几十 ms 启动开销）；
- 部分场景（UI 渲染、isReadOnly 判定）不需要精确 argv，shell-quote 已经够；
- WASM 在某些环境（外部 build）可能不可用。

新代码用 tree-sitter，老代码暂存。这是工程现实。

### 2. MAX_COMMAND_LENGTH = 10000

`parser.ts:21`：

```ts
const MAX_COMMAND_LENGTH = 10000
```

超过 10K 字符的命令 → 直接返回 null（parse-unavailable）→ 走 ask。

理由：tree-sitter 在病态输入下可能指数复杂度；10K 字符已经远超合理用例（正常 bash 命令最多 1K 字符）。`PARSE_ABORTED` 触发条件之一是 `(( a[0][0]... ))` 这种构造 ~2800 嵌套 subscript 的输入。

### 3. PARSE_ABORTED 也走 fail-closed

`ast.ts:444-457`：

```ts
if (root === PARSE_ABORTED) {
  // SECURITY: ... Previously indistinguishable from module-not-loaded → routed to
  // legacy (parse-unavailable), which lacks EVAL_LIKE_BUILTINS — `trap`,
  // `enable`, `hash` leaked with Bash(*). Fail closed: too-complex → ask.
  return {
    kind: 'too-complex',
    reason: 'Parser aborted (timeout or resource limit) — possible adversarial input',
    nodeType: 'PARSE_ABORT',
  }
}
```

这是一个**真实的回归修复**：之前 PARSE_ABORTED 被当成 `parse-unavailable` 路由到 legacy 路径，但 legacy 不识别 `trap`/`enable`/`hash` 这类 EVAL_LIKE_BUILTINS，攻击者用 2800 层嵌套的输入触发 PARSE_ABORTED → fallback 到 legacy → 用 `enable` 等命令绕权限。

修复：PARSE_ABORTED 单独识别，归为 too-complex 而不是 parse-unavailable。这种"两条相似路径在边界条件下差异"是工业代码常见的回归源。

### 4. 用 placeholder 桥接"AST 和 runtime"的差异

argv 是个静态字符串数组，但 bash runtime 有 `$()` / `$VAR` / glob expansion 这些动态行为。Claude Code 用 placeholder（`__CMDSUB_OUTPUT__` / `__TRACKED_VAR__`）**显式把"我们不知道运行时值"标记出来**——下游知道这些位置是"动态"，可以专门处理。

比这种思路更激进的做法是"完全静态分析"（要求所有值都是字面量），但那会拒绝太多正常用法（`for f in *.txt` / `NOW=$(date) && touch $NOW.log` 这类）。placeholder 在精确性和可用性之间做了平衡。

### 5. 注释 = 攻击向量与修复记录的混合

读 commands.ts 和 ast.ts 的注释能感受到——每一段都附带具体的攻击例子。如 `commands.ts:122-130` 那个 `echo "$\<NL>{}" ; curl evil.com` 例子，看了之后能立刻理解为什么需要 `commandOriginalJoined`。

这种"注释承载攻击场景"是这个项目的工程文化——比单纯写"why this code"更具体、更有信息量。

## 2.14 小结

- bash 难解析，必须 AST，regex 不够；
- 双路径：tree-sitter (4436 行 parser + 2679 行 ast) 走精确决策；shell-quote (1339 行 commands) 走 UI 等场景；
- 5 类 pre-check + tree-sitter + allowlist 节点游走 = fail-closed；
- `SimpleCommand{argv, envVars, redirects, text}` 是解析的核心数据结构；
- var scope 跨 `||`/`|`/`&` 必须重置（防 flag-omission 攻击）；
- placeholder（CMDSUB / TRACKED_VAR）桥接"AST 静态 vs runtime 动态"的差异；
- `BARE_VAR_UNSAFE_RE` 防 word-splitting / glob expansion 让 argv 和实际执行不一致；
- backslash-newline 续行必须计偶/奇数判定，防 `tr\<NL>aceroute` 这类攻击；
- `MAX_COMMAND_LENGTH = 10000` 防 ReDoS、PARSE_ABORTED fail-closed 防 fallback 漏洞；
- wrapper specs（7 个）让 `timeout 30 X` 的权限按 X 算。
