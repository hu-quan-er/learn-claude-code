# 00. 学习路线图

> 这一篇不讲源码，只回答一个问题：**接下来这十篇我应该怎么读，按什么顺序、配多少时间、读完应该能干什么。**
>
> 整套教程是带你"边读源码、边对照解读"，不是写好结论让你背。每一篇都会指明"打开哪个文件、看哪几行、关注什么"。如果你只想要结论速查，回去看 `topics/skill/01~04` 那四篇。

---

## 1. 这套教程的定位和它不做的事

先把范围划清楚，免得读一半发现走错地方。

### 这套教程做：

- 把 `restored-src/src/skills/` 及其周边（`tools/SkillTool/`、`commands.ts`、`processSlashCommand.tsx` 等）当成一份"可以逐行读"的源码来精读。
- 给每一段重要逻辑配上**精确文件路径 + 行号**。你读到一个引用，比如 `commands.ts:449-469`，就能立刻打开对应位置看到我在讲的代码。
- 把抽象概念（比如"`source` 和 `loadedFrom` 为什么要分开"）落到具体函数和具体字段上。
- 给出**端到端例子**：选定 `verify` 这个 bundled skill，从启动注册一路追到 prompt 注入，让你看到一条完整的命令路径，而不是分散的概念片段。
- 在每一节末尾留 2~3 个**对照思考题**，让你验证自己是不是真的看懂了，而不是被文档"灌"过去。

### 这套教程不做：

- 不是 Claude Code 用户手册。如果你想知道"怎么写一个 SKILL.md 给我自己用"，去看 `~/.claude/skills/` 现有 skill 或者官方 docs。
- 不重复讲 Claude Code 整体架构。本系列只聚焦 skill 模块。如果你不知道 `Tool`、`Command`、`Query` 的大致关系，先去看 `overview/01-核心架构与启动流程.md`。
- 不假装当前 `restored-src` 是完整的 Claude Code。这是从 sourcemap 还原回来的、有少量缺口的版本，比如 `skills/mcpSkills.ts` 不在快照里。我会在引用到这些缺口时**明确标注是反推还是直接证据**，不混着糊弄过去。

### 阅读这套教程的前置条件

读完之后会很顺的人具备这几样：

- 看得懂 TypeScript 的联合类型、字面量类型、`memoize`、`Promise.all` 这一类基本用法。
- 大致知道 Claude Code 是一个跑在终端里的 AI agent CLI，有「用户输入 → 模型 → 工具调用 → 结果」这条主链。
- 听说过"slash command"、"frontmatter"、"hooks"、"MCP"，不需要精通，混个脸熟即可。

如果上面三条全都不熟，先花一小时翻一下 `overview/00-总览与目录.md` 和 `overview/01-核心架构与启动流程.md`，再回来读这套。

读完整套之后，你应该能：

- **凭记忆画出** "从 `SKILL.md` 文件到模型 prompt block 的数据流"，并且每个环节能说出**至少一个具体函数名 + 它在哪个文件**。
- 对一个具体的 frontmatter 字段（比如 `paths`、`hooks`、`context: fork`），能说出**它在装载阶段被解析成什么、在执行阶段被谁读、读了之后有什么副作用**。
- 看到一段陌生的 skill 行为（比如"为什么这个 skill 在主目录看不到，进了子目录才看得到"），能**直接定位到大概在哪个函数里能找到答案**，而不是从头看一遍。
- 能区分"用户调用 skill"和"模型调用 skill"两条链路在哪里**复用**、在哪里**分叉**，能画出共享点和分叉点。
- 能解释为什么 skill **不只是 prompt 模板**，而是一个会临时改 `allowedTools`、可能切 `model`、可能 fork 子 agent、可能注册 hooks、可能在 compact 后保留的"执行策略包"。

## 3. 三种推荐读法

不同人需求不一样，给三条具体路线。

### 路线 A：完整精读（推荐第一次读）

按 `00 → 01 → 02 → ... → 10` 顺序读。

强调一点：**先读 01 那个 verify 端到端例子，再读 02 类型系统**。这个顺序是刻意的——很多类型字段单独看会觉得"为什么要有这个字段"，但你先在 01 里看过它在执行链路里被读取过一次，再回 02 看类型定义，理解会快得多。

### 路线 B：只想看"加载与聚合"（已经会用 skill，想读懂目录扫描和缓存）

读：`00 → 02 → 03 → 04 → 08`

跳过执行链路那一半。这条路线主要面向"想搞懂 skill 怎么从磁盘装进内存的"。

### 路线 C：只想看"执行与权限"（已经知道 skill 是从哪来的，想搞懂跑起来之后发生了什么）

读：`00 → 01 → 02 → 05 → 06 → 07 → 10`

跳过装载细节。重点在两条执行链以及它们如何共享 prompt 展开逻辑。

## 4. 阅读这套教程的方法

我建议你**两屏并排**：左边开 `restored-src/src/...` 的源码文件，右边开教程 markdown。每当我引用 `xxx.ts:NNN-MMM`，就跳到那段代码，看一眼，再回到文档。

不要试图"先把文档读完，再回头读代码"。这套教程是被设计成**和源码同步翻**的，文档本身不复述代码内容，只解释代码做了什么、为什么、和上下文怎么连。

每一节末尾会有**对照思考题**，类似这样：

> 思考：`getSkills(cwd)` 内部用了 `Promise.all` 并发拉四类来源，但其中两类（bundled、builtinPlugin）是同步函数。为什么还把它们放进 `getSkills`？这暴露了什么设计意图？

如果你看完一节回答不出来，**不要急着翻下一节**——回去再读一遍源码，或者看下一节是不是会回答。如果下一节也没回答，欢迎记下来等读完整套之后再回头看。

## 5. 关于源码版本与缺口

这套教程基于 `restored-src/`（即 `claude-code-2.1.88` sourcemap 还原版）。

我确认到的几个缺口：

- `restored-src/src/skills/mcpSkills.ts` 不在当前快照里，但 `services/mcp/client.ts`、`useManageMCPConnections.ts`、`mcpSkillBuilders.ts` 多处引用它。所以教程里**关于 MCP skill 的内部细节**会标注 "这是从调用方反推的，不是直接读 mcpSkills.ts 得出的"。
- `bundledSkills.ts` 里有些条件加载的 skill（比如 `dream`、`hunter`、`runSkillGenerator`）在 `bundled/` 目录里没有源文件。这些是 feature flag 控制的，当前快照不包含。教程不会引用这些。
- `restored-src/src/skills/bundled/` 目录下的 `index.ts` 包含一些 `feature('XXX')` 守卫，本教程引用 bundled skill 时会优先用**无 feature flag 守卫**的，比如 `verify`、`simplify`、`remember`、`stuck`、`batch`、`skillify`，避免在你机器上读出来对不上行号。

这些缺口都不影响主链路理解，但**遇到我标注"这是反推"的地方，请保留怀疑**——它们不是从 `restored-src` 直接读出来的事实。

## 6. 关于现有四篇文档与本教程的关系

`topics/skill/` 下原有的（结论型速查四篇）：

- `01-architecture-overview.md`
- `02-management-and-loading.md`
- `03-creation-and-definition.md`
- `04-usage-and-execution.md`

是**结论型速查文档**，告诉你"是什么、有哪些"。

而本教程 `guided-tour/` 是**过程型学习文档**，目标是带你**第一次**把这块代码读懂。

读法建议：

- 第一次接触 → 读 `guided-tour/`
- 已经读过、回头查某个细节 → 用原四篇
- 你会发现两套文档**在内容上有大量重叠**——这是有意的。`guided-tour/` 不是为了去重而存在的，是为了换一种"陪着读源码"的呈现方式。
