# 00 - 总览与源码地图

## 一句话定义

`AgentTool` 是 Claude Code 暴露给模型的一个普通 tool，名字就是 `Agent`。模型调用它就相当于"让我开一个新的 Claude 实例去干某件事"。整套子代理体系不是另一个进程或 RPC，而是在同一个 Node 进程里 fork 一份 query 循环，复用大部分父对话的运行时状态，只把消息/agentId/AbortController/transcript 隔开。

## 关键概念词汇表

| 术语 | 含义 |
|------|------|
| **agent / subagent** | 一个独立的 Claude 实例，由父代理通过 `Agent` 工具 spawn |
| **agentType** | agent 定义的类型标识，如 `Explore` / `Plan` / `general-purpose` / 用户自定义名 |
| **agentId** | 单次 spawn 的唯一 ID，由 `createAgentId()` 生成，用于隔离 AppState、transcript subdir、perfetto trace |
| **AgentDefinition** | agent 的元数据：whenToUse / tools / disallowedTools / model / systemPrompt 等 |
| **派发模式 (spawn mode)** | 5 种：同步直派 / async / teammate / remote / fork |
| **fork** | 特殊派发：省略 `subagent_type`，子代理继承父对话 messages，共享 prompt cache |
| **isolation** | `"worktree"`（git worktree 沙箱）或 `"remote"`（CCR 云端，ant 限定） |
| **mainLoopModel** | 父代理使用的模型，子代理在 `model: 'inherit'` 时继承它 |
| **toolUseContext** | 父代理传给工具的运行时上下文：appState、tools、agents、abortController、mcpClients 等 |
| **CacheSafeParams** | fork 启动时为了复用父 prompt cache 而必须保持不变的字段集合 |
| **ONE_SHOT_BUILTIN_AGENT_TYPES** | 一次性的内置 agent（不能 SendMessage 续聊），如 `statusline-setup` |
| **AgentMemoryScope** | `'user'` / `'project'` / `'local'`，agent 的持久记忆三层范围 |
| **TaskListId** | V2 Task tools 共用的任务列表 ID；子代理可以通过 agentId 继承独立 todo 空间 |

## 容易混淆的几对概念

- **agentType ≠ agentId**：`agentType` 是"派发哪种 agent"（如 `Explore`），`agentId` 是"这一次具体的 spawn 实例"（如 `agent-7f8e9...`）。同一类型 agent 可以同时 spawn 多个，每个有独立的 agentId。
- **fork ≠ isolation:"worktree"**：fork 是"子代理 messages 继承父对话"，目的是省 cache；worktree 是"子代理 cwd 切到独立 git worktree"，目的是 sandbox 文件改动。两者正交，可以同时启用。
- **subagent ≠ teammate**：默认 spawn 出来的是 subagent，结束就结束；teammate 是 swarm 模式下的"长期同事"，有独立 tmux pane 和 mailbox，能持续接受 SendMessage。teammate 的入口也是 `Agent`，但要传 `team_name + name`。
- **`AgentTool` 这个工具 ≠ `Agent` 这个名字**：源码里类型/文件名一律叫 `AgentTool`，但发给模型的工具 `name` 字段是 `Agent`（`AGENT_TOOL_NAME = 'Agent'`），也接受 legacy 别名 `Task`（`LEGACY_AGENT_TOOL_NAME`）。后者是历史命名遗留。
