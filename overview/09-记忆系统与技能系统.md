# 09 - 记忆系统与技能系统

---

## 一、记忆系统架构概述

### 1.1 目录结构

```
~/.claude/projects/<sanitized-git-root>/memory/
├── MEMORY.md              # 主索引（最多 200 行 / 25KB）
├── user_*.md              # 用户记忆（角色、偏好、知识）
├── feedback_*.md          # 反馈记忆（做法纠正/确认）
├── project_*.md           # 项目记忆（目标、截止日期、事件）
├── reference_*.md         # 参考记忆（外部系统指针）
├── logs/YYYY/MM/          # 每日日志（KAIROS 助理模式专用）
└── team/                  # 团队共享记忆（TEAMMEM 功能启用时）
    └── MEMORY.md
```

### 1.2 核心文件职责

| 文件 | 职责 |
|------|------|
| `src/memdir/memdir.ts` | 记忆加载、截断、系统提示构建 |
| `src/memdir/paths.ts` | 路径解析、验证、安全检查 |
| `src/memdir/memoryTypes.ts` | 记忆类型分类（user/feedback/project/reference） |
| `src/memdir/findRelevantMemories.ts` | 查询时记忆选择（通过 Sonnet 侧查询） |
| `src/memdir/memoryScan.ts` | 记忆文件发现与头部提取 |
| `src/memdir/memoryAge.ts` | 过期追踪与新鲜度标注 |
| `src/memdir/teamMemPaths.ts` | 团队记忆作用域与遍历保护 |
| `src/services/extractMemories/extractMemories.ts` | 后台记忆提取 Agent |

## 二、记忆文件格式与类型分类

### 2.1 文件格式（Frontmatter + 内容）

```markdown
---
name: {{记忆名称}}
description: {{一行描述 — 用于未来对话中判断相关性}}
type: {{user | feedback | project | reference}}
---

{{记忆内容}}
```

### 2.2 核心数据结构

**MemoryHeader**（扫描结果）：
```typescript
type MemoryHeader = {
  filename: string              // 相对路径 (e.g., 'user_role.md')
  filePath: string              // 绝对路径
  mtimeMs: number               // 修改时间（用于新鲜度/排序）
  description: string | null    // 来自 frontmatter
  type: MemoryType | undefined  // 来自 frontmatter
}
```

**EntrypointTruncation**（MEMORY.md 输出）：
```typescript
type EntrypointTruncation = {
  content: string              // 截断后的内容
  lineCount: number
  byteCount: number
  wasLineTruncated: boolean    // 超过 200 行
  wasByteTruncated: boolean    // 超过 25KB
}
```

### 2.3 四种记忆类型

| 类型 | 作用域 | 用途 | 示例 |
|------|--------|------|------|
| **user** | 始终私有 | 角色、专长、偏好、知识 | "深度 Go 经验，React 前端新手" |
| **feedback** | 默认私有（可团队） | 做法纠正/确认 | "集成测试必须使用真实数据库，不用 mock" |
| **project** | 倾向团队 | 目标、截止日期、事件、进行中的工作 | "合并冻结从 2026-03-05 开始" |
| **reference** | 通常团队 | 外部系统指针 | "Linear 项目 INGEST 跟踪管道 bug" |

### 2.4 不应保存的内容

- 代码模式、架构、文件路径 — 从 git/CLAUDE.md 推导
- Git 历史、blame 记录 — 用 `git log` 查询
- 调试解决方案 — 修复在代码中，上下文在提交信息中
- CLAUDE.md 中已记录的内容
- 临时任务细节 — 使用 Tasks 而非 Memory

## 三、记忆生命周期

### 3.1 写入生命周期

```
1. 系统提示注入（memdir.ts:buildMemoryLines）
   → 包含保存记忆的两步指令
   → 提供 frontmatter 格式示例
   → 说明四种类型的使用场景

2. 模型写入（通过 FileWriteTool）
   → 创建 memory/user_xyz.md（含 frontmatter）
   → 更新 MEMORY.md 索引（添加指针行）

3. 后台提取 Agent（extractMemories.ts）
   → 每轮查询结束时运行
   → 扫描对话记录中的可提取信息
   → 使用 formatMemoryManifest() 展示现有记忆
   → 如果主 Agent 已写入记忆，跳过重复范围
   → 否则从对话中提取新记忆并写入文件
```

### 3.2 读取生命周期

```
1. 系统提示构建（memdir.ts:loadMemoryPrompt）
   → 读取 MEMORY.md（索引文件）
   → 截断至最多 200 行 / 25KB
   → 注入系统提示
   → 通过 analytics 记录记忆计数

2. 查询时召回（findRelevantMemories.ts）
   → 扫描记忆目录中所有 .md 文件（最多 200 个，按 mtime 降序）
   → 读取每个文件的前 30 行（仅 frontmatter）
   → 将清单 + 查询 + 最近工具列表发送给 Sonnet
   → Sonnet 选择最多 5 个最相关的记忆
   → 返回路径 + mtime 用于新鲜度计算

3. 新鲜度标注（memoryAge.ts）
   → 超过 1 天的记忆获得过期警告
   → "记忆说 X 存在" ≠ "X 现在存在"
   → 模型必须验证声称的文件/函数/状态仍然存在
```

### 3.3 清理机制

- 手动清理：通过 `/remember` 技能审查并建议提升/删除
- DreamTask（KAIROS 模式）：每日日志 → 夜间蒸馏 → 主题文件 + MEMORY.md
- 用户可要求"忘记"条目触发删除
- 无自动定期清理调度

## 四、记忆路径安全

### 4.1 路径验证（paths.ts:validateMemoryPath）

```
安全检查清单：
✗ 相对路径 (../../foo)
✗ 根路径或近根路径 (/, /a)
✗ Windows 驱动器根 (C:\)
✗ UNC 路径 (\\server\share)
✗ 空字节
✓ NFC Unicode 规范化
```

### 4.2 路径解析优先级

```
1. CLAUDE_COWORK_MEMORY_PATH_OVERRIDE（环境变量，SDK/CCR 用）
2. settings.json 中的 autoMemoryDirectory（仅用户可信来源）
3. ~/.claude/projects/<sanitized-project-root>/memory/（默认）
```

### 4.3 团队记忆符号链接保护

```typescript
// teamMemPaths.ts:realpathDeepestExisting
// 1. 从目标路径向上遍历到第一个存在的祖先
// 2. 使用 realpath() 解析符号链接（非 path.resolve()）
// 3. 通过 lstat() + realpath() 组合检测悬挂符号链接
// 4. 路径键清理：拒绝 URL 编码的遍历、NFKC 规范化的 ../、反斜杠
```

### 4.4 写入权限豁免

- 自动记忆目录通过 `isAutoMemPath()` 检查自动获得写入权限
- 绕过 DANGEROUS_DIRECTORIES 限制
- 仅在非 SDK 覆盖路径（`!hasAutoMemPathOverride()`）时适用

## 五、记忆扫描与截断算法

### 5.1 扫描优化

```
单次遍历：
1. 读取所有文件的 frontmatter（每个文件仅前 30 行）
2. 按 mtime 降序排序
3. 最多 200 个文件（使用 Promise.allSettled 保证健壮性）
4. 最新文件优先用于相关性判断
```

### 5.2 截断策略

```typescript
// memdir.ts:truncateEntrypointContent
function truncateEntrypointContent(content: string): EntrypointTruncation {
  // 1. 行数上限优先（自然断行）
  if (lineCount > 200) → 截断到 200 行 + 添加警告

  // 2. 字节上限在最后换行处（防止行中截断）
  if (byteCount > 25600) → 在最后一个换行符处截断 + 添加警告

  // 3. 两个上限都在原始内容（截断前）上检查
  //    以捕获长行索引文件的情况
}
```

## 九、技能完整生命周期

### 9.1 注册与加载

**内置技能（编译时）**：
```
1. registerBundledSkill(definition) — 模块初始化时调用
2. 存储到模块级 bundledSkills: Command[] 数组
3. 引用文件在首次调用时延迟提取（files 属性）
4. 提取操作 memoized（并发调用共享同一 Promise）
```

**文件基技能（运行时发现）**：
```
1. 启动时（getSkillDirCommands，memoized）：
   → 遍历 managed / user / project / additional 技能目录
   → 同时加载 /skills/（目录格式）和遗留 /commands/
   → 通过 realpath() 解析文件路径进行去重
   → 分离条件（有 paths:）和无条件技能

2. 动态发现（文件变更触发）：
   → 从被修改文件的目录向上遍历到 cwd
   → 在每一级发现 .claude/skills/ 目录
   → 检查 gitignore 状态（跳过被忽略的目录）
   → 加载并合并到 dynamicSkills 映射（最深优先）
   → 触发 skillsLoaded 信号通知监听者

3. 条件激活（路径匹配）：
   → 有 paths: glob 模式的技能存储在 conditionalSkills 中
   → 当文件匹配模式时，技能被激活并加入无条件列表
   → 在 activatedConditionalSkillNames 中跟踪（会话内持久）
```

**目录格式约定**：
```
~/.claude/skills/
├── my-skill/
│   └── SKILL.md                 # 必须命名为 SKILL.md
├── namespace/
│   ├── nested-skill/
│   │   └── SKILL.md             # 技能名: namespace:nested-skill
```

### 9.2 执行流程

```
1. 触发方式
   → 用户输入 /skill-name arg1 arg2
   → 或模型通过 Skill 工具调用

2. 查找与验证
   → 按名称解析（精确匹配 → 别名匹配）
   → 检查 isEnabled() 回调（功能门控、环境变量）
   → 检查权限 canUseTool()
   → 验证 userInvocable 属性

3. 参数替换
   → 从 frontmatter arguments: 解析 argNames
   → 在提示中替换 ${arg1}, ${arg2}
   → 验证参数数量匹配声明

4. 提示生成（异步）
   → 如果设置了 skillRoot，前置 "Base directory: ..."
   → 替换 ${CLAUDE_SKILL_DIR} → 技能目录
   → 替换 ${CLAUDE_SESSION_ID} → 会话 ID
   → 执行 Shell 命令（!`...` / ```! 块）
     仅限非 MCP 技能（MCP 为不可信远程）
   → 返回 ContentBlockParam[]

5. 执行上下文
   → inline（默认）：技能提示注入当前对话
   → fork：作为子 Agent 在独立上下文中运行

6. 钩子注册
   → 技能的 hooks 属性在执行期间注册
   → 作用域限定于该次调用（不持久）

7. 完成
   → 结果返回给模型或用户
   → 钩子取消注册
```

### 9.3 斜杠命令到技能的解析

```
用户输入: /command-name args
         ↓
解析器提取命令名和参数字符串
         ↓
在合并的命令注册表中查找（内置 + 文件 + MCP + 插件）
         ↓
匹配: 精确名称 → 别名 → 命名空间:子命令
         ↓
调用 getPromptForCommand(args, context)
         ↓
通过正常提示命令执行路由
```

## 十、技能安全机制

### 10.1 内置技能文件提取安全

```typescript
// 延迟提取，首次调用时执行
// memoized Promise（并发调用共享同一次提取）
// 安全写入标志：O_EXCL | O_NOFOLLOW
//   O_EXCL → 文件已存在则失败
//   O_NOFOLLOW → 不跟随符号链接
// 权限 0o700/0o600（仅所有者可访问）
// 目录路径包含进程级随机数（主要符号链接防御）
```

### 10.2 Shell 注入防御

```
1. 技能 frontmatter 声明 allowed-tools: [Bash(npm:*)]
2. 内联脚本（!` 块）仅允许非 MCP 技能执行
3. MCP 技能来自远程/不可信来源：Shell 执行被禁止
4. Shell 命令在参数替换后、模型看到结果前执行
```

### 10.3 功能门控示例

```typescript
// /remember 仅在自动记忆启用时可见
isEnabled: () => isAutoMemoryEnabled()

// /dream 仅在 KAIROS 功能启用时编译
if (feature('KAIROS') || feature('KAIROS_DREAM')) {
  registerDreamSkill()
}
```

## 十二、对比总结

| 维度 | 记忆系统 | 技能系统 |
|------|----------|----------|
| **持久化** | 文件在 ~/.claude/projects/... | 运行时注册 + 文件 |
| **更新频率** | 每轮（提取 Agent） | 启动时加载 + 动态发现 |
| **安全重点** | 路径遍历、符号链接攻击 | Shell 注入、工具权限 |
| **数量限制** | 最多 200 文件、25KB MEMORY.md | 最多 200 文件基技能 |
| **集成模式** | 提示注入 + 侧查询 | 命令注册 + 钩子 |
| **去重机制** | 内容哈希（MEMORY.md） | 文件身份（realpath） |
| **用户交互** | 自动（含 /remember 审查） | 手动 /skill-name 或模型调用 |
