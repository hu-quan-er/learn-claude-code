# 05 - 命令系统与 UI 组件

## 一、命令系统架构

### 1.1 命令注册机制

**文件**: `src/commands.ts`, `src/types/command.ts`

所有命令在 `commands.ts` 中集中注册，使用 `memoize` 函数缓存命令列表。

命令分为三种类型：

| 类型 | 说明 |
|------|------|
| `PromptCommand` (type: 'prompt') | 向 Claude 模型发送内容块的命令 |
| `LocalJSXCommand` (type: 'local-jsx') | 使用 React 组件渲染的本地命令 |
| `LocalCommand` (type: 'local') | 不使用 JSX 的本地命令 |

### 1.2 PromptCommand 结构

```typescript
type PromptCommand = {
  type: 'prompt'
  name: string
  description: string
  progressMessage: string             // 执行期间显示的消息
  contentLength: number               // 内容大小（令牌估计）
  source: 'builtin' | 'mcp' | 'plugin' | 'bundled'
  argNames?: string[]                 // 命令参数名称
  allowedTools?: string[]             // 允许使用的工具列表
  model?: string                      // 覆盖默认模型
  context?: 'inline' | 'fork'         // 执行上下文
  effort?: EffortValue                // 努力级别
  getPromptForCommand(args, context): Promise<ContentBlockParam[]>
}
```

### 1.3 LocalJSXCommand 结构

```typescript
type LocalJSXCommand = {
  type: 'local-jsx'
  name: string
  description: string
  isEnabled?: () => boolean
  load: () => Promise<LocalJSXCommandModule>  // 延迟加载
}
```

使用 **延迟加载** 模式，只有在命令被调用时才加载重型依赖，优化启动性能。

### 1.4 命令执行流程

```
1. 命令解析 — 用户输入 /command-name args
2. 命令查找 — 从已注册命令列表中查找
3. 权限检查 — 检查 isEnabled()
4. 参数处理 — 提取和验证参数
5. 执行：
   ├─ PromptCommand → getPromptForCommand() → 发送到 Claude API
   ├─ LocalJSXCommand → load() → call() → React 组件渲染
   └─ LocalCommand → 直接执行逻辑
6. 完成回调 — onDone() 处理结果
```

### 1.5 动态命令来源

```
getCommands() [memoized]
  ├─ 内置命令 (commit, review, diff 等)
  ├─ 插件命令 (getPluginCommands)
  ├─ 技能目录命令 (getSkillDirCommands)
  ├─ 动态技能命令 (getDynamicSkills)
  └─ MCP 命令 (getMcpToolsCommandsAndResources)
```

## 二、核心命令功能说明

### 2.1 系统与配置命令

#### `/help` — 帮助菜单
- **类型**: LocalJSXCommand
- **功能**: 显示所有可用命令的交互式列表，支持搜索和分类

#### `/config` — 配置管理
- **类型**: LocalJSXCommand
- **功能**: 打开 Settings 组件，管理用户配置
- **选项卡**: Config、Usage、Status

#### `/model` — 模型选择
- **类型**: LocalJSXCommand
- **功能**: 交互式模型选择器，支持快速模式
- **特性**: 模型列表、Opus 1M/Sonnet 1M 访问检查、快速模式切换、Effort 级别设置

#### `/init` — 初始化项目文档
- **类型**: PromptCommand
- **功能**: 初始化 CLAUDE.md、.claude/skills/、.claude/settings.json
- **流程**:
  1. 询问用户要设置什么
  2. 探索代码库（manifest、README、CI 配置等）
  3. 创建 CLAUDE.md、CLAUDE.local.md
  4. 建议并创建 skills 和 hooks

### 2.2 代码审查与分析命令

#### `/review` — 本地代码审查
- **类型**: PromptCommand
- **流程**: `gh pr list` → `gh pr view` → `gh pr diff` → 生成审查报告

#### `/ultrareview` — 深度远程代码审查
- **类型**: LocalJSXCommand
- **功能**: 10-20 分钟深度 bug 发现和验证
- **特点**: 运行在 Claude Code on the Web 上

#### `/doctor` — 诊断工具
- **类型**: LocalJSXCommand
- **功能**: 系统诊断和故障排除

#### `/compact` — 会话压缩
- **类型**: LocalCommand
- **策略**:
  1. 尝试会话记忆压缩 (SM-compact)
  2. 运行微压缩 (microcompact)
  3. 传统压缩（调用压缩模型汇总历史）
  4. 后处理清理

### 2.3 权限与计划命令

#### `/permissions` — 权限管理
- **类型**: LocalJSXCommand
- **功能**: 显示并管理权限规则，支持重试被拒绝的命令

#### `/plan` — 计划模式
- **类型**: LocalJSXCommand
- **功能**: 启用计划模式，显示当前计划
- **流程**: 检查是否已在计划模式 → 启用 → 显示计划文件

#### `/mcp` — MCP 管理
- **类型**: LocalJSXCommand
- **子命令**: `/mcp enable|disable|reconnect <name>`

### 2.4 会话与历史命令

#### `/resume` — 恢复会话
- **类型**: LocalJSXCommand
- **输入方式**: 会话 ID、标题模糊匹配、交互式选择器
- **特性**: 跨项目恢复、工作树支持

#### `/status` — 会话状态
- **功能**: 显示当前会话、模型、权限模式、上下文窗口等信息

#### `/session` — 会话管理
- **功能**: 管理会话（列表、删除、归档）

### 2.5 任务与执行命令

#### `/tasks` — 后台任务管理
- **功能**: 显示和管理后台任务（异步代理、远程会话、Shell、Dream 等）

#### `/fast` — 快速模式
- **功能**: 切换快速模式（降低延迟的低成本回复）

### 2.6 实用工具命令

#### `/diff` — 差异查看
- **功能**: 显示 git 差异或回合变更
- **视图**: 文件列表视图、详细差异视图

#### `/export` — 导出会话
- **功能**: 导出会话为 HTML、Markdown 等格式

#### `/clear` — 清除缓存
- **子命令**: `/clear conversation`、`/clear caches`

### 2.7 完整命令清单

从 `src/commands/` 目录分析，Claude Code 包含约 **80+** 个命令目录，涵盖：

```
系统管理: help, config, model, doctor, status, upgrade
会话操作: resume, session, clear, compact, export, share
代码操作: review, diff, plan, branch, rename, rewind
权限控制: permissions, sandbox-toggle, privacy-settings
MCP/插件: mcp, plugin, skills, reload-plugins
任务管理: tasks, agents
UI 控制: theme, color, output-style, vim, voice
调试工具: debug-tool-call, heapdump, stats, ctx_viz, perf-issue
以及更多...
```

### 3.1 提示输入组件（PromptInput）

**文件**: `src/components/PromptInput/`

#### 核心组件
- **PromptInput.tsx** — 主输入组件（~1000+ 行）
  - 多模式支持: Normal、Search（Ctrl+R）、Vim

- **PromptInputModeIndicator.tsx** — 模式指示器
- **PromptInputHelpMenu.tsx** — 帮助菜单

#### 输入处理 Hooks
| Hook | 功能 |
|------|------|
| `useInputBuffer()` | 管理输入文本缓冲区 |
| `useArrowKeyHistory()` | 上下箭头历史导航 |
| `useHistorySearch()` | Ctrl+R 历史搜索 |
| `usePromptSuggestion()` | 提示建议（AI 生成） |
| `useTypeahead()` | 自动补全 |
| `useCommandQueue()` | 待处理命令队列 |
| `useKeybindings()` | 可配置快捷键 |

#### 自动补全与建议
```
- 斜杠命令 (/) → findSlashCommandPositions()

- Slack 频道 (#) → findSlackChannelPositions()
- 思考触发 (@thinking) → findThinkingTriggerPositions()
```

## 四、消息类型与数据结构

### 4.1 基本消息类型

```typescript
type Message = AssistantMessage | UserMessage | SystemMessage | ToolResultMessage

// 助手消息
type AssistantMessage = {
  role: 'assistant'
  content: ContentBlock[]        // TextBlock, ToolUseBlock, ThinkingBlock
  usage?: Usage
}

// 用户消息
type UserMessage = {
  role: 'user'
  content: ContentBlockParam[]
}

// 工具结果消息
type ToolResultBlockParam = {
  type: 'tool_result'
  tool_use_id: string
  content: string
  is_error?: boolean
}
```

### 4.2 消息元数据

```typescript
interface Message {
  uuid: string                    // 唯一会话 ID
  type: 'user' | 'assistant' | ...

  message: ContentBlockParam | Content[]
  sourceToolAssistantUUID?: string  // 工具使用者
  cost?: number
  apiError?: string
}
```

## 五、会话历史管理

### 5.1 本地历史

**文件**: `src/history.ts`

- **最大历史项目数**: 100
- **粘贴内容存储**:
  - 小于 1024 字符的内容内联存储
  - 大型内容使用哈希引用存储到外部文件

关键函数：
```
makeHistoryReader()        — 异步生成器，逆向读历史
expandPastedTextRefs()     — 替换 [Pasted text #N] 占位符
parseReferences()          — 解析粘贴引用
```

### 5.2 远程会话历史

**文件**: `src/assistant/sessionHistory.ts`

- **分页大小**: 100 events per page
- **API 端点**: `{baseUrl}/v1/sessions/{sessionId}/events`
- **分页策略**:
  - `fetchLatestEvents()` — 使用 `anchor_to_latest`
  - `fetchOlderEvents()` — 使用 `before_id` 游标
