## 一、权限控制系统（Permission System）

### 1.1 权限模式架构

**文件**: `src/utils/permissions/PermissionMode.ts`

Claude Code 实现了 7 种权限模式：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| `default` | 每个工具使用时都需要用户确认 | 标准交互模式 |
| `plan` | 停止自动执行，让用户验证计划 | 复杂任务规划 |
| `acceptEdits` | 自动接受编辑工具的修改 | 信任编辑场景 |
| `bypassPermissions` | 完全绕过权限检查 | 管理员/CI |
| `dontAsk` | 不再提示，直接执行 | 自动化场景 |
| `auto` | 基于转录分类器自动判断（Anthropic 内部） | 内部使用 |
| `bubble` | 权限拒绝升级到父级（内部使用） | Agent 嵌套 |

### 1.2 权限规则体系

**规则结构**：
```typescript
PermissionRule = {
  toolName: string           // 工具名称（Bash、Read、Edit 等）
  ruleContent?: string       // 可选规则内容（路径、命令模式等）
  behavior: 'allow' | 'deny' | 'ask'
  source: SettingSource      // 规则来源
}
```

**规则来源层级**（优先级从高到低）：
```
1. policySettings   → 管理员策略（MDM/managed-settings.json）
2. projectSettings  → 项目级（CLAUDE.md）
3. userSettings     → 用户级（~/.claude/settings.json）
4. globalSettings   → 全局（~/.claude/settings.json global scope）
```

### 1.3 权限检查流程

**文件**: `src/utils/permissions/permissions.ts`（52KB）

```
hasPermissionsToUseTool(tool, input, toolUseContext)
  ↓
根据工具类型调用特定权限检查器：
  ├─ Bash 工具    → bashPermissions.ts（含自动模式分类器）
  ├─ 文件编辑    → filesystem.ts（路径验证 + 危险文件检测）
  ├─ 文件读取    → filesystem.ts（路径读取权限）
  └─ 其他工具    → 默认允许或工具特定逻辑
  ↓
返回 PermissionResult {
  behavior: 'allow' | 'deny' | 'ask',
  decisionReason: { type, classifier?, rule? },
  updatedInput?: 修改后的输入（如清理重定向）
}
```

### 1.4 文件系统权限

**文件**: `src/utils/permissions/filesystem.ts`（62KB）

**危险文件保护**：
```typescript
DANGEROUS_FILES = [
  '.gitconfig', '.gitmodules', '.bashrc', '.bash_profile',
  '.zshrc', '.zprofile', '.profile', '.ripgreprc',
  '.mcp.json', '.claude.json'
]

DANGEROUS_DIRECTORIES = ['.git', '.vscode', '.idea', '.claude']
```

**路径验证机制**：
- 符号链接检测 — 防止跨边界访问
- 路径遍历检测 — 阻止 `../` 逃逸
- 工作目录限制 — 核心 vs 额外允许的目录
- UNC 路径检查 — Windows 网络路径安全

### 1.5 自动模式分类器（Auto-Mode Classifier）

**文件**: `src/utils/permissions/yoloClassifier.ts`（52KB）

```
在 auto 模式下：
- 对 Bash 命令进行 AI 分类，判断是否安全
- 调用侧查询 Claude API 的小模型进行决策
- 支持用户自定义 allow/soft_deny/environment 规则
- 权限匹配失败时回退到提示模式
```

**危险模式检测**：
```javascript
isDangerousBashPermission(toolName, ruleContent)
- 完全允许 Bash（无 ruleContent）
- 解释器前缀规则：python:*、node:* 等
- 通配符匹配：python*、node* 等
```

### 1.6 权限更新持久化

```
操作：
- applyPermissionUpdate()              // 在内存应用规则
- persistPermissionUpdates()           // 写入磁盘
- deletePermissionRuleFromSettings()   // 删除规则
- 支持"永远允许"快速配置
```

## 二、Hooks 系统

### 2.1 Hook 事件类型

**文件**: `src/schemas/hooks.ts`

#### 工具执行 Hooks
| 事件 | 说明 |
|------|------|
| `PreToolUse` | 工具执行前（输入为 JSON 工具参数） |
| `PostToolUse` | 工具执行后（包含 inputs 和 response） |
| `PostToolUseFailure` | 工具执行失败（包含 error 信息） |
| `PermissionDenied` | 权限被拒绝 |

#### 会话生命周期 Hooks
| 事件 | 说明 |
|------|------|
| `SessionStart` | 会话开始 |
| `SessionEnd` | 会话结束 |
| `SetupHook` | 初始化设置 |
| `StopHook` | 停止信号 |
| `FileChanged` | 文件变化 |
| `CwdChanged` | 工作目录变化 |

#### 其他 Hooks
| 事件 | 说明 |
|------|------|
| `Notification` | 通知事件 |
| `ConfigChange` | 配置变化 |
| `InstructionsLoaded` | 指令加载 |
| `SubagentStart/Stop` | 子代理生命周期 |

### 2.2 Hook 类型

#### 1. 命令 Hook（BashCommandHook）
```json
{
  "type": "command",
  "command": "shell command",
  "if": "Bash(git *)",
  "shell": "bash|powershell",
  "timeout": 30,
  "statusMessage": "Running...",
  "once": false,
  "async": false,
  "asyncRewake": false
}
```

#### 2. Prompt Hook（LLM 评估）
```json
{
  "type": "prompt",
  "prompt": "Analyze this: $ARGUMENTS",
  "model": "claude-opus-4-1-20250805",
  "timeout": 60
}
```

#### 3. Agent Hook（子代理执行）
```json
{
  "type": "agent",
  "agentName": "custom-agent",
  "prompt": "Process: $ARGUMENTS",
  "timeout": 120
}
```

#### 4. HTTP Hook
```json
{
  "type": "http",
  "url": "https://webhook.example.com",
  "method": "POST|GET|PUT",
  "headers": {"Auth": "Bearer token"}
}
```

### 2.3 Hook 执行框架

**文件**: `src/utils/hooks.ts`

```
executeHookMatchers(event, input)
  ↓
1. 从配置加载所有 Hook 匹配器
2. 按优先级排序（sortMatchersByPriority）
3. 逐个执行匹配的 Hook：
   ├─ 命令 Hook → execCommandHook()
   │  ├─ 生成唯一占位符防注入
   │  ├─ 设置 hook 环境变量
   │  ├─ 执行 shell 命令
   │  └─ 解析 JSON 输出
   │
   ├─ Prompt Hook → execPromptHook()
   │  ├─ 用 $ARGUMENTS 替换占位符
   │  ├─ 调用 Claude API 侧查询
   │  └─ 提取 structured output
   │
   ├─ Agent Hook → execAgentHook()
   │  ├─ 生成子代理任务
   │  └─ 运行多轮对话
   │
   └─ HTTP Hook → execHttpHook()
      ├─ 构建 HTTP 请求
      └─ 解析响应
  ↓
4. 收集结果（HookResult[]）
5. 应用到模型（如权限重写）
```

### 2.4 Hook 配置管理

**配置优先级**：`托管 > 插件 > 项目 > 用户 > 内置`

**限制机制**：
- `shouldAllowManagedHooksOnly()` — 仅允许托管 Hook
- `shouldDisableAllHooksIncludingManaged()` — 完全禁用 Hook

### 2.5 Hook 安全性

- 随机占位符防止恶意命令注入
- JSON 输入验证
- Shell 转义（`shellQuote.ts`）
- 权限规则过滤（`if` 条件）
- 超时控制

## 三、配置管理系统（Settings System）

### 3.1 配置来源层级

**文件**: `src/utils/settings/settings.ts`（32KB）

```
优先级从高到低：
1. policySettings   → MDM/管理员托管设置
   └─ /etc/anthropic/claude-code/managed-settings.json
   └─ /etc/anthropic/claude-code/managed-settings.d/*.json

2. projectSettings  → 项目级配置
   └─ CLAUDE.md frontmatter

3. userSettings     → 用户级配置
   └─ ~/.claude/settings.json

4. globalSettings   → 全局 scope
   └─ ~/.claude/settings.json（当前工作目录外）

5. pluginSettings   → 插件设置
   └─ ~/.claude/plugins/<name>/settings.json
```

### 3.2 配置 Schema

**文件**: `src/utils/settings/types.ts`（42KB）

```typescript
SettingsJson = {
  // 权限配置
  permissions: {
    allow: PermissionRule[]
    deny: PermissionRule[]
    ask: PermissionRule[]
    defaultMode: PermissionMode
    additionalDirectories: string[]
  }

  // Hooks 配置
  hooks: { [HookEvent]: HookCommand[] }

  // 工具配置
  tools: { [toolName]: { allow?, deny?, ask? } }

  // 其他
  environmentVariables: Record<string, string>
  sandboxConfig: SandboxSettings
  disableSandbox?: boolean
}
```

### 3.3 配置加载流程

```
getInitialSettings()
  ├─ 按优先级顺序加载各来源
  ├─ 校验每个来源的规则（filterInvalidPermissionRules）
  ├─ 合并配置（mergeWith）
  │  ├─ 数组覆盖（不合并）
  │  └─ 对象递归合并
  └─ 返回合并后的 SettingsJson
```

**缓存机制**：
- `getCachedSettingsForSource()` — 源级缓存
- `getSessionSettingsCache()` — 会话级缓存
- 变化检测器（`changeDetector.ts`）监听文件变化

## 四、沙箱机制（Sandbox System）

### 4.1 沙箱概述

**文件**: `src/utils/sandbox/sandbox-adapter.ts`（35KB）

- 基于 `@anthropic-ai/sandbox-runtime` 包装
- 提供文件系统/网络访问限制
- 与 Claude Code 设置系统集成

### 4.2 沙箱限制配置

**文件系统限制**：
```
- allowedReadPaths: string[]     // 允许读取的目录
- allowedWritePaths: string[]    // 允许写入的目录
- deniedReadPaths: string[]      // 拒绝读取的目录
- deniedWritePaths: string[]     // 拒绝写入的目录
```

**网络限制**：
```
- allowedHosts: NetworkHostPattern[]
- deniedHosts: NetworkHostPattern[]
- allowLocalhost: boolean
- allowPrivateIps: boolean
- denyAll: boolean
```

### 4.3 权限到沙箱的映射

```
权限规则 → SandboxRuntimeConfig

例：
- Bash(cd /var/*) → allowedReadPaths: ['/var/*']
- Read(/home/user/**) → allowedReadPaths: ['/home/user/**']
- Edit(src/) → allowedWritePaths: ['./src/**']
```

## 五、Shell 命令执行安全

### 5.1 Bash 解析器

**文件**: `src/utils/bash/bashParser.ts`（130KB）

```
原始命令字符串
  → splitCommandWithOperators()    [命令/操作符分割]
  → 提取 here-docs（heredoc.ts）  [处理 << 重定向]
  → 解析 continuation lines       [处理 \<newline>]
  → shell-quote 解析              [参数分割]
  → 重定向提取                    [output redirections]
  → AST 结构
```

**关键安全机制**：
- 随机占位符（防注入）：`__SINGLE_QUOTE_<salt>__`
- Heredoc 提取（防护 `<<`）
- Continuation line 处理（防止 `\<newline>` bypass）
- 重定向检查（防止输出到危险位置）

### 5.2 重定向控制

**拒绝的重定向目标**：
- 包含 `$` 变量的目标
- 包含反引号的目标
- 包含 `*/?/[]/{}` 通配符
- 包含 `~` 家目录扩展
- 以 `!` 开头（历史扩展）
- 以 `=` 开头（Zsh 扩展）
- 以 `&` 开头（文件描述符）

### 5.3 多层安全检查

| 层级 | 机制 | 检查项 |
|------|------|--------|
| 1 | 语法分析 | AST 解析、不完整命令检测 |
| 2 | 危险模式 | 命令替换 `$()`、`${}`、过程替换 `<()` |
| 3 | Zsh 漏洞 | zmodload、emulate、mapfile 等 |
| 4 | 注入检测 | 未转义反引号、引号嵌套错误 |
| 5 | sed 校验 | sed 命令安全列表 |
| 6 | 路径验证 | 工作目录约束、path traversal 检查 |
| 7 | 只读模式 | 只读命令白名单 |
| 8 | 权限规则 | `Bash(*)` 通配符匹配 |

## 六、Git 集成

**文件**: `src/utils/git/gitFilesystem.ts`（22KB）

## 十、纵深防御安全架构总结

```
应用层权限
  ↓
Tool 级权限检查（Bash/Read/Edit 等）
  ↓
文件路径验证（符号链接、遍历检查）
  ↓
危险文件/目录保护
  ↓
Sandbox 沙箱限制（可选）
  ↓
Shell 命令解析安全（random placeholders）
  ↓
操作系统进程隔离
```

### 拒绝机制流程

```
1. 权限规则检查（allow/deny/ask）
   ↓
2. 自动模式分类（如启用）
   ↓
3. 危险模式检测
   ↓
4. 用户提示（if not auto-approved）
   ↓
5. Hook 回调（PermissionDenied hook）
   ↓
6. 执行或拒绝
```
