## 一、应用启动流程

### 1.1 Entry Point（入口点）

**文件**: `src/entrypoints/cli.tsx`

`cli.tsx` 是整个应用的入口，其 `main()` 函数实现了**极度优化的启动路径**：

```
进程启动 → cli.tsx (main() 函数)
  ↓
特殊快速路径检查（零模块加载）:
  • --version/-v     → 直接输出版本号
  • --dump-system-prompt → 输出系统提示词
  • --chrome-native-host → Chrome集成
  • --daemon-worker   → 后台工作进程（仅内部）
  • bridge/remote     → 远程控制模式
  • daemon             → 守护进程
  • ps/logs/attach/kill → 会话管理
  • --worktree --tmux  → Tmux快速路径
  ↓
（其他路径）→ 加载完整 CLI
  • enableConfigs()
  • startCapturingEarlyInput()
  • 动态导入 ../main.tsx → cliMain()
```

**设计要点**：
- 每条快速路径实现零模块加载，追求极致的启动速度
- 使用 `profileCheckpoint()` 在多个位置记录启动阶段耗时
- 采用动态 `import()` 推迟重型模块加载

### 1.2 Bootstrap 初始化

**文件**: `src/entrypoints/init.ts`

`init()` 函数是 memoized 的启动器，确保只执行一次：

#### 阶段一：配置
1. `enableConfigs()` — 验证并启用配置系统
2. `applySafeConfigEnvironmentVariables()` — 应用安全环境变量（在信任对话前）
3. `applyExtraCACertsFromConfig()` — 在第一个 TLS 握手前应用 CA 证书

#### 阶段二：基础设施
4. `setupGracefulShutdown()` — 注册退出清理处理器
5. `configureGlobalMTLS()` — 配置双向 TLS
6. `configureGlobalAgents()` — 配置 HTTP 代理/mTLS 代理
7. `preconnectAnthropicApi()` — 预连接 API 以重叠 TCP+TLS 握手

#### 阶段三：后台初始化（异步，无阻塞）
8. `initialize1PEventLogging()` — 第一方事件日志
9. `populateOAuthAccountInfoIfNeeded()` — OAuth 缓存填充
10. `initJetBrainsDetection()` — IDE 检测
11. `detectCurrentRepository()` — Git 仓库检测
12. `initializeRemoteManagedSettingsLoadingPromise()` — 远程设置加载
13. `initializePolicyLimitsLoadingPromise()` — 策略限制加载

#### 阶段四：特殊功能
14. `initUpstreamProxy()` — CCR 模式下的上游代理（仅 `CLAUDE_CODE_REMOTE=true`）
15. `ensureScratchpadDir()` — 初始化暂存目录

#### 阶段五：遥测
16. `initializeTelemetryAfterTrust()` — 在信任建立后初始化 OpenTelemetry

### 1.3 Main 启动

**文件**: `src/main.tsx`（核心应用启动器）

#### 顶层侧效应（在导入前）
- `profileCheckpoint('main_tsx_entry')`
- `startMdmRawRead()` — MDM 设置并行读取
- `startKeychainPrefetch()` — macOS 钥匙链并行预取

#### 迁移
- 运行存储在 `.claude/settings.json` 的同步迁移
- 示例: `migrateSonnet1mToSonnet45()`, `migrateOpusToOpus1m()`

#### CLI 解析（Commander.js）
- 设置 slash 命令（`/commit`, `/review` 等）
- 解析 CLI 标志（`--model`, `--permission-mode` 等）
- 注册插件命令和 MCP 命令

#### 会话启动
- 调用 `init()` — 完整启动序列
- 显示信任对话（如果需要）
- 加载插件和 MCP 服务器
- 初始化工具权限上下文

#### UI 启动
- 创建 Ink 根组件（`renderAndRun()`）
- 挂载 React 应用树（App.tsx）
- 启动 REPL 主循环

## 三、Query 引擎与主循环

### 3.1 QueryEngine

**文件**: `src/QueryEngine.ts`

QueryEngine 是高层 API 入口，支持 SDK 和 REPL 两种模式：

```typescript
class QueryEngine {
  private mutableMessages: Message[]
  private readFileState: FileStateCache
  private totalUsage: NonNullableUsage

  async *submitMessage(
    prompt: string | ContentBlockParam[],
    options?: { uuid?: string; isMeta?: boolean }
  ): AsyncGenerator<SDKMessage>
}
```

### 3.2 核心查询循环

**文件**: `src/query.ts`

```typescript
async function* query(params: QueryParams): AsyncGenerator<StreamEvent | Message> {
  while (turnCount < maxTurns) {
    // 1. 准备消息
    const messages = normalizeMessagesForAPI(state.messages)

    // 2. API 请求（流式）
    const response = await api.beta.messages.stream({
      model, max_tokens, system: systemPrompt, messages
    })

    // 3. 处理流事件
    for await (const event of response) {
      yield event  // 转发给 UI
    }

    // 4. 检查完成原因
    switch (response.stop_reason) {
      case 'tool_use':
        // 执行工具 → 继续
        for (const toolUse of toolUses) {
          const result = await executeToolWithPermissions(toolUse)
          state.messages.push(toolResultMessage)
        }
        continue

      case 'end_turn':
        return { type: 'complete' }  // 完成

      case 'max_tokens':
        // 自动继续（如果有预算）
        continue
    }
  }
}
```

### 3.3 关键状态机

```
初始化
  ↓
用户输入 → 创建消息 → 正规化 → API 请求
  ↓
流事件处理:
  ├─ content_block_start  → 创建块
  ├─ content_block_delta  → 累积内容
  ├─ content_block_stop   → 完成块
  ├─ message_delta        → 更新使用统计
  └─ message_stop         → 最终 stop_reason
  ↓
stop_reason 分析:
  ├─ 'end_turn'       → 返回（完成）
  ├─ 'tool_use'       → 执行工具 → 继续循环
  ├─ 'max_tokens'     → 恢复 → 继续循环
  └─ 'stop_sequence'  → 返回（用户停止）
```

## 四、终端 UI 渲染引擎

### 4.1 概述

Claude Code 使用**自定义 Ink 渲染器** — 基于 `react-reconciler` 实现的 React 终端 UI。

### 4.2 架构层次

```
React 组件树 (App.tsx)
  ↓
reconciler.ts (React → DOM 协调)
  • createInstance()  — 创建 ink-box, ink-text, ink-link 元素
  • appendChildNode() — 构建树
  • setAttribute()    — 应用属性和样式
  ↓
DOM 树 (dom.ts)
  • DOMElement
    - yogaNode (Yoga 布局)
    - children
    - style / textStyles
    - eventHandlers
  ↓
Yoga 布局引擎 (native-ts/yoga-layout)
  • calculateLayout() — Flexbox 计算
  ↓
渲染管道 (ink.tsx)
  • onComputeLayout() — 计算布局
  • onRender()        — 渲染到屏幕缓冲
    - renderNodeToOutput() — DOM → 字符单元格
    - writeDiffToTerminal() — 最小 ANSI diff
  ↓
Terminal Output (stdout)
```

### 4.3 Ink 主类

**文件**: `src/ink/ink.tsx`

```typescript
class Ink {
  // 屏幕缓冲区对象池
  frontFrame: Frame        // 当前显示的帧
  backFrame: Frame         // 下一帧在此构建
  stylePool: StylePool     // 重用样式对象
  charPool: CharPool       // 重用字符
  hyperlinkPool: HyperlinkPool

  // 输入处理
  focusManager: FocusManager
  selection: SelectionState
  hoveredNodes: Set<DOMElement>

  // 渲染周期
  scheduleRender: () => void  // throttled @ 33.33ms (30fps)

  onRender(): void {
    // 1. 应用选择覆盖层
    // 2. 计算屏幕损伤区域（旧帧 vs 新帧）
    // 3. 发出 ANSI 补丁到终端
  }
}
```

### 4.4 React 协调器

**文件**: `src/ink/reconciler.ts`

```typescript
const reconciler = createReconciler({
  createInstance(type, props): DOMElement {
    // type: 'ink-box' | 'ink-text' | 'ink-virtual-text' | 'ink-link'
    const node = createNode(type)
    applyProps(node, props)
    return node
  },

  resetAfterCommit(rootNode) {
    rootNode.onComputeLayout()  // 1. Yoga 布局
    rootNode.onRender()         // 2. 调度渲染
  }
})
```

### 4.5 Frame（屏幕缓冲区）

```typescript
type Frame = {
  viewport: { width: number; height: number }
  cells: Map<`${x},${y}`, Cell>
  cursor: { x: number; y: number; visible: boolean }
}

type Cell = {
  char: string
  style: Style      // 颜色、粗体、斜体、下划线、背景
  hyperlink?: string // OSC 8 链接
}
```

### 4.6 渲染循环

```
React setState()
  → reconciler.batchedUpdates()
  → createInstance / updateInstance
  → resetAfterCommit()
    ├─ onComputeLayout() [Yoga]
    └─ onRender() [调度]
  → queueMicrotask()  // 推迟到 React layout effects 后
  → Ink.onRender()
    ├─ 应用选择覆盖层
    ├─ renderNodeToOutput()    [DOM → Frame]
    ├─ applySearchHighlight()
    ├─ 计算 ANSI 损伤差异
    ├─ writeDiffToTerminal()   [Frame → ANSI]
    └─ stdout.write()
```

### 4.7 关键性能优化

1. **Frame 对象池** — 重用 Cell 对象以减少 GC 压力
2. **最小 ANSI 差异** — 只发送屏幕变化部分，跳过未改变的行和单元格
3. **Throttled Render** — `scheduleRender()` 限制在 33.33ms（30fps），多个 setState 在一帧内合并
4. **选择和搜索** — 选择覆盖层在 `onRender()` 中应用，不修改背景 Frame

## 五、协调器与 Agent 系统

### 5.1 Coordinator Mode

**文件**: `src/coordinator/coordinatorMode.ts`

协调器是 Claude Code 的 Agent 编排模式，用于任务分解和并行执行。

**启用条件**：
```typescript
isCoordinatorMode() {
  return feature('COORDINATOR_MODE') &&
         isEnvTruthy(process.env.CLAUDE_CODE_COORDINATOR_MODE)
}
```

### 5.2 协调器角色

协调器从系统提示中获得以下能力：

1. **角色定义** — 是编排者，不是独立执行者
2. **Worker 工具** — `Agent`（生成新 worker）、`SendMessage`（继续现有 worker）、`TaskStop`（停止 worker）
3. **并发管理**：
   - 读取工作（研究）— 自由并行
   - 写入工作（实现）— 一次一个
   - 验证 — 独立 worker

### 5.3 协调器工作流示例

```
用户: "修复 auth 模块中的 null 指针"
  ↓
协调器（合成研究规范）:
  Agent({ description: "调查 auth bug", prompt: "调查 src/auth/ 中的 null 指针..." })
  Agent({ description: "研究 auth 测试", prompt: "查找 src/auth/ 的所有测试..." })
  ↓
  [并行研究中...]
  ↓
task-notification: agent-a1b completed: "在 src/auth/validate.ts:42 找到 null 指针..."
  ↓
协调器（合成实现规范）:
  SendMessage({ to: "agent-a1b", message: "修复 src/auth/validate.ts:42 的 null 指针..." })
  ↓
  [修复进行中...]
```

### 5.4 Worker 结果格式

```xml
<task-notification>
  <task-id>{agentId}</task-id>
  <status>completed|failed|killed</status>
  <summary>{human-readable summary}</summary>
  <result>{agent's final text response}</result>
  <usage>
    <total_tokens>N</total_tokens>
    <tool_uses>N</tool_uses>
    <duration_ms>N</duration_ms>
  </usage>
</task-notification>
```
