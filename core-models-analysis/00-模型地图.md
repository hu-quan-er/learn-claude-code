# 00. 模型地图 — 7 个核心 model 的关系总览

> 这一篇做一件事：用一张图、一份对照表、一段串讲，把 Claude Code 的 7 个核心 model 摆到关系网里。每个 model 一行简介 + 主要源码位置 + 在网里的角色——读完这篇能决定接下来重点看哪几个，或确认你已经有大致地图。

---

## 1. 7 个核心 model 一览

| 篇 | Model | 核心源码 | 行数 | 一句话定位 |
|---|---|---|---|---|
| 01 | **Command** | `types/command.ts` | 217 | 所有可被用户敲 `/foo` 或模型 `SkillTool({skill})` 调用的能力的统一抽象 |
| 02 | **Tool** | `Tool.ts` | 792 | 模型可以发 `tool_use` 调用的本地能力的统一接口 |
| 03 | **Message** | `utils/messages.ts` 反推 | (缺) | conversation 数组的 6 大类元素：user / assistant / system / attachment / progress / tombstone |
| 04 | **AppState** | `state/AppStateStore.ts` | 569 | 全局唯一可变状态——95+ 字段覆盖所有子系统 |
| 05 | **Permission** | `types/permissions.ts` | 441 | 权限规则、决策、原因——allow/deny/ask/passthrough × 8 source × 11 reason |
| 06 | **Hook** | `types/hooks.ts` | 290 | 27 种生命周期事件 + 每事件特化 schema 的扩展点 |
| 07 | **Plugin** | `types/plugin.ts` | 363 | 第三方扩展容器——其它 6 个 model 的来源之一 |

加起来**不到 3000 行类型定义**就把整个 agent CLI 的核心结构表达完了——非常密。

## 3. 三种关系："谁包含谁 / 谁引用谁 / 谁影响谁"

把上面的图按关系分类：

### 3.1 "包含"关系（嵌入子模型）

| 父 model | 子 model | 在父里以什么字段 |
|---|---|---|
| AppState | Permission（ToolPermissionContext） | `toolPermissionContext` |
| AppState | Plugin（LoadedPlugin[]） | `plugins.enabled` / `plugins.disabled` |
| AppState | Command（Command[]） | `mcp.commands` / `plugins.commands` |
| AppState | Tool（Tool[]） | `mcp.tools` |
| AppState | Hook（SessionHooksState） | `sessionHooks` |
| AppState | Message[] | 通过 `tasks[*].messages` 等 |
| Plugin（LoadedPlugin） | Hook（HooksSettings） | `hooksConfig` |
| Plugin（manifest） | Command 间接 | 通过 `commandsPath` 装载 |
| Command（PromptCommand） | Plugin（PluginManifest） | `pluginInfo.pluginManifest` |
| Tool（ToolUseContext） | Message[] | `messages` 字段 |

### 3.2 "引用"关系（关联但不嵌入）

| Model A | Model B | 引用方式 |
|---|---|---|
| Tool.checkPermissions 返回 | PermissionResult | 调用时 |
| ToolResult.newMessages 含 | Message[] | tool 完成后注入 |
| ToolResult.contextModifier 修改 | ToolUseContext | tool 完成后改 |
| Hook 触发时 | Tool 调用栈 | hook event 关联 toolUseID |
| Command.getPromptForCommand 返回 | ContentBlockParam[]（Message 内容） | 包成 user message |
| Permission.decisionReason 可能是 | Hook（reason: 'hook'） | 决策溯源 |

### 3.3 "影响"关系（运行时副作用）

- Command 的 `allowedTools` / `model` / `effort` 影响 → AppState
- Hook 的 `additionalContext` 影响 → 下一 turn 的 prompt
- Hook 的 `permissionDecision` 影响 → Permission decision
- Permission 的 mode 影响 → 所有 tool 的 checkPermissions
- Plugin 的 mcpServers 影响 → AppState.mcp.tools
- Tool 的 contextModifier 影响 → 后续 turn 的 ctx

## 5. 这套 model 没覆盖什么

诚实说明这 7 个 model **不是** Claude Code 的全部——以下是没专门讲的：

| 没覆盖 | 在哪 | 为什么没专讲 |
|---|---|---|
| **Settings** | `utils/settings/types.ts` | 是配置层，结构上是平的对象 |
| **Logs / SessionLog** | `types/logs.ts` (330 行) | 持久化 + recovery 用，独立子系统 |
| **TextInputTypes** | `types/textInputTypes.ts` (387 行) | 输入处理，UI 内部 |
| **Ids** | `types/ids.ts` (44 行) | 简单 branded types |
| **MCP Server / Resource** | `services/mcp/types.ts` | 协议层，不是 model 主体 |
| **Agent Definition** | `tools/AgentTool/loadAgentsDir.ts` | 子 agent 配置，类似 skill 但更简单 |
| **TodoList / Task** | `tasks/types.ts` | task 子系统 |
| **FileHistoryState** | `utils/fileHistory.ts` | undo / redo 子系统 |

如果你需要研究某个具体子系统，从对应文件入手——但**理解了 Tier 1 的 7 个 model 后，其它都是它们的延伸或专项**。

## 6. 这套 model 揭示的 Claude Code 设计风格

读完所有 7 篇后，会发现以下 reflexes 反复出现（08 篇深入）：

1. **discriminated union 重度使用** — 几乎每个 model 都有 `type` 字段判别
2. **schema-first** — zod schema 作为 SDK / config 的契约
3. **type-first error 设计** — 30+ 种 PluginError，多数还没真用
4. **immutable + react-friendly** — DeepImmutable 在能用的地方
5. **可见性 / 可调用性独立维度** — 每个布尔字段一个意图
6. **来源标签 first-class** — `source` / `loadedFrom` 都是核心字段
7. **callback-as-API** — onProgress / onDone / setAppState 等
8. **巨型 context 做信封** — ToolUseContext 50+ 字段、AppState 95+ 字段

每一条都是有意为之，08 篇展开。
