# 完整数据流示例（三轮对话）

> 源码版本：claude-code 2.1.88
> 分析日期：2026-04-12

---

## 场景设定

模拟一个真实的 Claude Code 使用场景，覆盖以下关键路径：

| 轮次 | 用户行为 | 触发机制 |
|------|----------|----------|
| **Round 1** | 用户首次输入文本问题 | 会话初始化 + 系统提示构建 + 首次 API 调用 |
| **Round 2** | 模型调用工具（Read + Edit），用户确认 | 工具执行 + 工具结果注入 + 多轮 tool_use 循环 |
| **Round 3** | 对话接近上下文窗口阈值，触发自动压缩 | Token 计数 + 自动压缩 + 压缩后重建 |

**环境假设**：
- Provider: `firstParty`（1P API）
- Model: `claude-sonnet-4-6`（默认 Sonnet）
- 上下文窗口: 200K tokens
- 工作目录: `/home/user/my-project`（Git 仓库）
- 已配置: 项目级 `CLAUDE.md`，2 个 MCP server
- Feature flags: `CACHED_MICROCOMPACT=on`, `TRANSCRIPT_CLASSIFIER=on`

### Step 1.3: 消息归一化

**入口**: `normalizeMessagesForAPI(messages, filteredTools)`

此时消息列表只有 2 条消息：

```
归一化前的 messages 数组:

messages[0] = {                           ← prependUserContext 注入的合成消息
  type: "user",
  isMeta: true,
  message: {
    role: "user",
    content: [{ type: "text", text: "<system-reminder>...CLAUDE.md...</system-reminder>" }]
  }
}

messages[1] = {                           ← 用户实际输入
  type: "user",
  message: {
    role: "user",
    content: "帮我看下 src/utils/config.ts 这个文件，有个 bug 导致配置加载失败"
  }
}
```

**13+ 遍流水线处理**（大部分 pass 在此轮无实际变更，但全部执行）：

```
Pass 1: reorderAttachments()              → 无附件，跳过
Pass 2: filterVirtualMessages()           → 无虚拟消息，跳过
Pass 3: stripMediaFromErrorResponses()    → 无媒体错误，跳过
Pass 4: 消息类型分流处理                    → user 消息正常通过
Pass 5: stripToolReferenceBlocks()        → 无 tool_reference（首轮），跳过
Pass 6: stripCallerField()                → 无 tool_use（首轮），跳过
Pass 7: filterOrphanedThinkingOnly()      → 无 thinking 块，跳过
Pass 8: filterTrailingThinking()          → 无 assistant 消息，跳过
Pass 9: filterWhitespaceOnly()            → 无空白消息，跳过
Pass 10: smooshSystemReminders()          → 检测到 <system-reminder> 但无 tool_result 可嵌入，保留原位
Pass 11: sanitizeErrorToolResults()       → 无 error tool_result，跳过
Pass 12: ensureNonEmptyAssistant()        → 无 assistant 消息，跳过
Pass 13: injectMessageIdLabels()          → 为每条消息注入 UUID 标签（HISTORY_SNIP 启用时）
Pass 14: validateImages()                 → 无图片，跳过

关键: 连续 user 消息合并
  messages[0](meta user) + messages[1](real user)
  → mergeUserMessages() → 合并为单条 user 消息
  → content 变为 array:
    [
      { type: "text", text: "<system-reminder>...CLAUDE.md...</system-reminder>" },
      { type: "text", text: "帮我看下 src/utils/config.ts 这个文件，有个 bug 导致配置加载失败" }
    ]
```

**归一化后**: 1 条 user 消息

  │   ├── 下降 > 2000 tokens? YES
  │   └── 客户端变更? NO
  │   → 归因: "5m TTL 过期" (非客户端错误)
  └── cache_creation: ~8,300 (重新写入 org scope)

T+5min10s+
  ├── global scope: 仍在命中 (TTL=1h)
  └── org scope: 重新创建后命中

T+12min (Round 3，压缩触发)
  ├── 消息数组重建
  ├── system + tools 不变 → 缓存前缀仍然有效
  ├── 消息部分: 内容变化 → cache_creation 重新写入
  └── global scope 段落: 仍然命中 (< 1h)
```

### messages 数组演变

```
Round 1 (发送前):
  [0] user: { <system-reminder>CLAUDE.md</> + "帮我看下..." }
  共 1 条

Round 1 (发送后):
  [0] user: { ... }
  [1] assistant: { thinking + text + tool_use:Read }
  共 2 条

Round 2 (Read 结果后，发送前):
  [0] user: { ... }
  [1] assistant: { thinking + text + tool_use:Read }
  [2] user: { tool_result:Read }
  共 3 条

Round 2 (Edit 结果后，最终回复后):
  [0] user
  [1] assistant (Read call)
  [2] user (Read result)
  [3] assistant (Edit call)
  [4] user (Edit result)
  [5] assistant (最终回复)
  共 6 条

... 持续增长到 82 条 ...

Round 3 (压缩后):
  [0] user: { <session-memory>摘要</> + <system-reminder>CLAUDE.md</> }

  [41] user: { "现在帮我把所有改动提交一下" }
  共 42 条 (从 83 条压缩)

### 缓存状态机

```
                    ┌──────────────────┐
                    │     FRESH        │  首次写入
                    │  cache_creation  │
                    └────────┬─────────┘
                             │ 下次请求
                    ┌────────▼─────────┐
                    │     CACHED       │  缓存命中
                    │   cache_read     │  ←── 后续每轮在此循环
                    └────────┬─────────┘
                             │ TTL 过期 / 内容变更
                    ┌────────▼─────────┐
                    │    EXPIRED       │  缓存失效
                    │ cache_creation   │  重新写入
                    └────────┬─────────┘
                             │ 下次请求
                    ┌────────▼─────────┐
                    │     CACHED       │  重新命中
                    └──────────────────┘
```

## 异常路径示例

### 如果 Round 3 的 Session Memory 压缩失败

```
trySessionMemoryCompaction() 返回 null (可能原因: SM 过旧、tokens 不足)

级联回退:
  → compactConversation()                   ← 全量压缩
    ├── 发送 API 请求 (querySource: "compact")
    │   ├── model: "claude-sonnet-4-6"
    │   ├── 输入: 全部 82 条消息
    │   └── 输出预留: 20,000 tokens
    │
    ├── API 返回摘要:
    │   "本次会话中，用户在 my-project 项目中修复了多个 bug..."
    │
    ├── 构建压缩后 messages:
    │   [0] user: { "以下是之前对话的摘要:\n\n..." }
    │   [1] user: { "现在帮我把所有改动提交一下" }
    │
    ├── 后置恢复资源:
    │   ├── 最近 5 个访问文件的内容 (≤50K tokens)
    │   └── 活跃技能的描述 (≤25K tokens)
    │
    └── 如果 API 返回 413 (Prompt Too Long):
        ├── 截断最旧轮次
        └── 重试 (最多 3 次)

如果全量压缩也失败:
  → consecutiveAutoCompactFailures++
  → 达到 3 次 → 断路器触发 → 停止自动压缩
  → 直接发送 (可能遇到 context overflow)
  → withRetry 中 context overflow 处理:
      ├── 解析错误消息中的 inputTokens / contextLimit
      ├── 计算 adjustedMaxTokens
      └── 用更小的 max_tokens 重试
```
